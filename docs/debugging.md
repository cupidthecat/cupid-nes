# Debugger and Lua

Cupid exposes one debugger service to the desktop tools and Lua scripts. The same service handles instruction control, breakpoints, memory inspection, PPU viewers, disassembly, watches, and tracing. Inspection reads use dedicated peek paths. They do not acknowledge the APU frame IRQ, clear PPU status, advance controller shift registers, change mapper read latches, or trigger FDS status-read automation.

Open Tools > Debugging > Debugger to inspect the running game in a separate resizable
window. Drag its title bar to place it beside the game or on another display.
Memory and PPU Viewers and Lua Scripting also have their own windows. Opening
or focusing these tools leaves gameplay and audio running; Pause, breakpoints,
and stepping commands control when the machine stops.

## Execution control and breakpoints

The debugger supports execute, CPU-read, and CPU-write breakpoints over an address or inclusive address range. Execute breakpoints stop before the matching instruction. Read and write breakpoints record the access and pause at the instruction boundary after the access completes, so the hardware bus transaction itself remains complete.

Step Into executes one instruction and stops before the next instruction. Step Over treats a `JSR` as one operation and stops at its return address with the original stack depth. Other instructions behave like Step Into. Step Out runs until the current subroutine returns to the caller's stack depth. Debugger pause state is connected to the normal frontend execution control, so a breakpoint also pauses the shared frame runner and audio path.

Frame Advance can continue from a debugger stop to the end of the current frame while leaving emulation paused. A breakpoint on either machine of a dual VS cabinet stops the shared runner. Pausing audio retains its queued samples and reconstruction state.

The disassembler covers all 256 opcode values, including undocumented instructions. Operands show their addressing mode, and relative branches show the destination address. Inspection reads only the bytes belonging to each instruction.

CPU memory inspection covers `$0000-$FFFF`. PPU memory inspection covers `$0000-$3FFF`. The hardware viewers copy current nametable, pattern-table, palette, and primary OAM data without performing normal CPU or PPU register reads. Mapper-backed pattern and nametable reads use the currently selected banks.

## Inline assembler

Open Tools > Debugging > 6502 Assembler to preview one instruction and write it
to writable memory. Choose CPU address space, Internal CPU RAM, or Cartridge
RAM, then enter the instruction's CPU address. Use current PC copies the program
counter into that field. The address field accepts debugger expressions such as
`PC + #2`; unprefixed numbers in that field are hexadecimal.

Enter an instruction such as `LDA #$42`, `STA $0010`, or `BNE $0080`, then choose
Preview instruction. Generated bytes shows the address, encoded bytes, and
length. Target backing identifies the mapped storage. Existing disassembly at
preview shows six instructions currently in memory, so you can check what the
write will replace.

Instruction operands accept decimal numbers, `$hex`, `0xhex`, and `%binary`.
For example, `LDA 16` selects zero page `$10`, while `LDA $0010` forces absolute
addressing. An immediate value can be -128 through 255. Branch operands name
the destination address, which must be within -128 through +127 bytes of the
next instruction. Mnemonics and index registers are case-insensitive. Accumulator
shifts accept either `ASL` or `ASL A`. A semicolon starts a comment on the same
line. Each entry is limited to 127 characters; labels, directives, expressions
inside instruction operands, and multiline assembly are not supported.

All official instructions are supported, along with undocumented instructions
whose mnemonic and addressing mode identify one encoding. Implied `NOP` uses
`EA`, and immediate `SBC` uses `E9`. Ambiguous undocumented forms report an error;
use the hex editor when you need to select their exact bytes.

Pause the game and choose Apply instruction to write the previewed bytes. Every
byte must have writable physical backing in the selected address space. ROM,
registers, unmapped addresses, and protected memory are read-only. All target
choices use CPU addresses, including the cartridge RAM window at `$6000-$7FFF`.
An instruction that crosses a protected boundary is rejected as a whole.

Changing a field, resetting or replacing the game, or resuming execution requires
a new preview. Apply also checks that the target bytes and their mapped backing
still match the preview. A changed instruction clears rewind and run-ahead
history; a preview, rejected write, or write of identical bytes preserves it.
Writes are disabled during movie recording, playback, rewind, and netplay.
Applying an instruction changes live RAM only, and the game can overwrite it
after resuming. The cartridge file is unchanged.

## Memory Search and Cheat Finder

Open Tools > Debugging > Memory Search. Select a memory space, an inclusive address
range, and an 8-, 16-, or 32-bit value. Values can be shown as hex, unsigned
decimal, or signed decimal. Alignment limits candidates to addresses divisible
by the selected width. New search captures the first values. Changing the space,
range, width, format, or alignment starts a new search.

Filter with Equal, Different, Greater, Less, At least, or At most. Compare against
a constant, the last sample, the initial value, another address, or the last
successful filter. Refresh captures current values without filtering; Undo
restores the previous capture or filter. Sort by clicking a column heading and
use the page controls to browse results. A selected result can be copied, added
to Memory Watches, or sent to the cheat editor.

Tools > Cheats > Cheat Finder uses the same search controls. For a CPU-space
result, choose a byte, replacement value, optional compare byte, and description.
Send to cheat editor creates a draft; Test as enabled cheat adds a live cheat that
you can disable or remove through Cheats. The compare byte tests the original
mapped value. PPU, OAM, and palette results can become watches but not CPU cheats.
Testing cheats is disabled during movies, rewind, and netplay.

Reset, power cycle, state restoration, and game replacement invalidate saved
snapshots. Search and watch reads do not consume device reads. If a watch panel
cannot accept a new result, the handoff reports an error and retains the existing
watch list and selected search result.

## Memory Watches

Open Tools > Debugging > Memory Watches. Add a watch by choosing a memory space,
address expression, width, and display format. Expressions accept debugger
arithmetic and registers, such as `PC + #2`; unprefixed numbers are hex. Watches
support 8-, 16-, 24-, and 32-bit little-endian values in hex, unsigned, signed,
binary, or ASCII form. Add array creates consecutive rows. The list holds 64
watches; an invalid expression or range leaves existing watches intact.

Capture previous saves the current values as a baseline. Freeze previous keeps
that baseline while current values change; otherwise Previous tracks the value
before the latest change. Columns can be sorted, rows moved, and the table
copied or exported as CSV. Unavailable addresses remain listed with an error.
Search results and hex selections can add watches directly. Reads are
side-effect-free.

## Hex / Memory Editor

Open Tools > Debugging > Hex / Memory Editor. Inspect CPU RAM, cartridge RAM,
CPU or PPU address space, sprite OAM, or palette memory. Go / select accepts an
address expression and byte count. The grid shows hex, ASCII, and changed-byte
markers; Backing / protection identifies the mapped storage. Shift-click,
dragging, and Shift-arrow extend a selection. Page Up/Down changes pages,
Ctrl+Home/End jumps to the ends, Ctrl+C/Ctrl+V copies and pastes, and Ctrl+F/F3
searches and finds the next match.

Live view updates the page; turn it off to keep a captured page. Refresh takes
another capture, and Reset changed bytes sets a new baseline. Find bytes / text
accepts hex pairs or UTF-8 text and can wrap. Binary import/export uses files.
Text clipboard copies reject embedded NULs and invalid UTF-8.

Pause a live game and enable Live view before replacing bytes, pasting, or
importing. ROM, protected, register-only, and unmapped targets are checked before
any write. A changed value clears rewind and run-ahead history; a rejected or
identical write leaves it intact. Edits are disabled during movies, rewind, and
netplay. Add watch / array can turn a selection into watches.

## Visual PPU tools

Open **Tools > Debugging > PPU tools** to choose a viewer. Each opens in its own
resizable window and follows the loaded game. The game keeps running until you
pause it. Live views refresh at most 30 times per second; Frozen holds a snapshot,
and Refresh takes another. The footer records its frame, scanline, and dot.

| Tool | What it shows |
| --- | --- |
| Pattern tables | Both pattern tables, with background or sprite palettes and CPU, background, or sprite bank selection |
| Nametables | All four logical nametables, decoded tiles or attribute colors, and the selected tile's addresses and palette |
| Sprites and OAM | All 64 sprites in an OAM grid or at their screen positions, with size, flips, priority, coordinates, and tile address |
| PPU debugger | Control, mask, status, scrolling latches, OAM address, banks, scanline, dot, and cycle count |
| VRAM inspector | Hexadecimal PPU memory from `$0000` to `$3FFF`, or 256 bytes of primary OAM, with a scrollbar and address entry |
| Tile editor | An enlarged 8 by 8 tile with four pixel values and palette selection |
| PPU palettes | The 32 palette RAM entries, including their mirrored addresses |

Click an image to select a tile, sprite, or palette entry. Double-click a pattern
tile to open it in the tile editor. Arrows move the selection; the mouse wheel
moves through rows. Grid toggles outlines. Export PNG saves the displayed graphics
without the grid or selection outline through a Save dialog.

Pause the game and leave Live enabled to edit. In VRAM or palettes, select a byte
and choose Edit byte, press Enter, or double-click it. Addresses and byte values
are hexadecimal. In the tile editor, choose a pixel value from 0 through 3 and
click the tile to paint. The tile editor keeps the pattern viewer's bank selection;
select CPU banks before painting mapped memory. CHR ROM, unmapped memory, and protected pages are read-only.
Writable CHR, nametable RAM, palette RAM, and OAM edits affect the running machine;
they do not modify the cartridge file. The game can overwrite RAM after resuming.
Undo or Ctrl+Z reverses the last edit while its memory and frame still match.
Edits clear rewind history and are disabled during movies, rewind, and netplay.

The viewers inspect mapped memory without clocking the PPU bus or consuming
mapper fetch state. MMC5 background and sprite bank views and extended nametable
attributes are decoded separately. Nametables show the current mapping, not a
reconstruction of bank changes or split windows across a completed frame. The
sprite position view includes all sprites, without the rendering limit of eight
per scanline or background occlusion. Registers are read-only in the PPU debugger;
Frame advances through the shared execution controls.

Settings > General saves **Live PPU viewers** and **PPU viewer grid** as defaults
for newly opened viewers. Each open window can change these independently.

## Lua scripts

Lua scripts run on the embedded Lua 5.4 runtime. File, operating-system, package-loading, and network libraries are not opened. Each script load and callback invocation receives a configurable instruction budget. Exceeding it faults the script instead of allowing an unbounded callback to stall emulation.

The `emu` table provides these debugger operations:

- `emu.read(address)` performs a side-effect-free CPU-space read.
- `emu.readWord(address)` reads a little-endian CPU word without device side effects.
- `emu.readRange(address, count)` returns a one-based table of up to 4,096 CPU bytes. The range must fit in the 64 KiB address space.
- `emu.readPpu(address)` performs a side-effect-free PPU-space read.
- `emu.write(address, value)` performs a normal CPU bus write, including device and mapper side effects.
- `emu.getRegister(name)` and `emu.setRegister(name, value)` access `A`, `X`, `Y`, `PC`, `SP`, and `P`/`status`.
- `emu.getPpuState()` returns the current control, mask, status, VRAM-address, scroll, scanline, dot, frame, and PPU-cycle fields.
- `emu.getCpuCycleCount()` returns the current CPU cycle count.
- `emu.getFrameCount()` returns the completed PPU frame count. `emu.getRegion()` returns the current timing region name.
- `emu.addMemoryCallback(type, first[, last], function)` registers `read`, `write`, or `exec` callbacks and returns an ID. `emu.removeMemoryCallback(id)` removes it.
- `emu.pause()` and `emu.resume()` use the same execution state as the desktop debugger.
- `emu.log(text)` appends to the script log.
- `emu.drawPixel`, `emu.drawLine`, `emu.drawRectangle`, and `emu.clearOverlay` draw to a 256 by 240 ARGB diagnostic overlay. Drawing is clipped and bounded to that surface.

An execute callback runs immediately before the CPU executes the instruction at its address. A read callback runs after the real hardware read and receives `(address, value)`. Returning an integer from 0 through 255 replaces the value delivered to the CPU without repeating the device read. A write callback runs after the real hardware write and receives `(address, value)`; its return value is ignored. Callbacks triggered by writes made from inside another Lua callback are suppressed until the outer callback returns, which prevents recursive script loops around `emu.write`.

Script runtime errors mark the current script faulted. Further callbacks from that script stop until it is reloaded. Unloading a script drops all registered callback references, clears its log state, and clears the diagnostic overlay.
